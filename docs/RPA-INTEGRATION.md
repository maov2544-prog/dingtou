# 影刀接入指南（RPA 侧）

> 目标读者：**写影刀流程的人**。读完这份就能把「扫表 → 提交 → 轮询 → 写回」接起来。
> 服务端接口细节见 [`API-CONTRACT.md`](./API-CONTRACT.md)；部署见 [`DEPLOY.md`](./DEPLOY.md)。

---

## 0. 一句话说清职责边界

| 谁 | 干什么 | **不干什么** |
|---|---|---|
| **影刀** | 读素材表、提交待投放的行、拿 `cells` 写回表、推企微 | ❌ 不算 N、❌ 不判场景、❌ 不调千川 |
| **本服务** | 定位账户、查计划、算 N、判 A/B/C1/C2、调千川、返回要写什么 | ❌ 不写 Excel（只返回「写哪些格子」） |

**判断规则（A/B/C1/C2）全在服务里**。规则改了只改服务，影刀不用动。

---

## 1. 完整流程

```
① 影刀扫素材表：找出「投放状态 = 待投放」且「K 投放类型 = 空」的行
        ↓
② 影刀 POST /api/v1/task/processPending    提交整批（带行号 + 抖音号 + 商品名 + 视频id）
        ↓
③ 服务内部：按【抖音号+商品】去重 → 定位账户 → 查计划 → 算 N → 判场景 → 执行
        ↓
④ 服务返回 cells（要写哪些格子）              ← 若返回 code=4，先轮询 GET /api/v1/task/{taskId}
        ↓
⑤ 影刀按 cells 写回素材表：K 投放类型 / N 投放状态
        ↓
⑥ 影刀推企微通知（可选）
```

### 素材表要读/写的列

| 列 | 表头 | 用途 |
|---|---|---|
| 行号 | — | 写回时定位（**1-based，含表头**） |
| `D` | 抖音号 | 提交 `awemeShowId` |
| `G` | 产品 | 提交 `productName` |
| `H` | 视频id | 提交 `videoId`（**就是抖音视频ID**，19 位数字） |
| `K` | 投放类型 | **筛选条件**（为空才处理）+ **写回** |
| `N` | 投放状态 | **筛选条件**（= 待投放才处理）+ **写回** |

> ⚠️ **筛选条件是 `投放状态=待投放` 且 `K 投放类型=空`**，两个都要满足。
> `K` 非空 = 老数据 / 已处理过，**一律跳过**。
>
> ### 🔴 2026-10-07 新增：还要捞「昨天标记了投放中」的行
>
> 服务遇到「该组合还有随心推在投放中」时，会在 `N 投放状态` 写 **`投放中 10.7`**（带**检测当天**日期）。
> 因为**投放中建不了计划**，所以要等它跑完。
>
> **影刀的筛选要改成：**
> ```
> 投放状态 = 待投放
>   或
> （投放状态 以「投放中」开头 且 里面的日期 ≠ 今天）
> ```
>
> - **日期 = 今天** → 当天已检测过，**不再扫**（避免同一天反复检测同一行）
> - **日期 < 今天** → 第二天自动顺延重测；仍是投放中就把日期覆盖成新的，
>   不投放中了就正常走 A/B/C1/C2
>
> 📌 日期格式是 `M.D`（如 `投放中 10.7`），与素材表其他日期一致，**无前导零**。
> 📌 服务**只写 `N 投放状态`**，**不动 `K 投放类型`** —— 因为它其实还没投，只是暂时跳过。

## 2. 影刀流程伪代码

```
待投放行 = 素材表.筛选(行 =>
        行.N_投放状态 == "待投放"
    AND 行.K_投放类型 == 空
)

如果 待投放行.数量 == 0:
    日志("没有待投放的行")
    结束

请求体 = {
    "requestId": "batch-" + 当前时间戳 + "-" + 随机数,     // ⚠️ 每次必须换新的！
    "params": {
        "rows": 待投放行.映射(行 => {
            "row":          行.行号,
            "awemeShowId":  行.D_抖音号,
            "productName":  行.G_产品,
            "videoId":      行.H_视频id        // 可空；有就传，能少一次定位
        })
    }
}

应答 = HTTP_POST("http://127.0.0.1:8080/api/v1/task/processPending", 请求体, token)

// ---- 处理 code=4（任务转后台了）----
如果 应答.code == 4:
    循环 最多 60 次:                      // 约 10 分钟
        等待 10 秒
        应答 = HTTP_GET("http://127.0.0.1:8080/api/v1/task/" + 应答.taskId, token)
        如果 应答.code != 4: 跳出循环
    如果 应答.code == 4:
        报错并上报人工("任务一直没结束，taskId=" + 应答.taskId)
        结束

如果 应答.code != 0:
    上报人工(应答.message)                // ⚠️ 不要重试
    结束

// ---- 写回 ----
对 应答.data.cells 里的每个 cell:
    素材表.写(cell.row, cell.column, cell.value)

// ---- 汇报 ----
如果 应答.data.failed > 0 或 应答.data.skipped > 0:
    日志("⚠️ 本批没有全部办成，明细：")
    对 应答.data.results 里 status != OK 的每一项:
        日志("  " + 项.awemeShowId + " + " + 项.productName + "：" + 项.warnings)
    上报人工(明细)                        // 这些要人工补数据或稍后重跑
```

### 三条必须记住的

1. **`requestId` 每次都要换新的** —— 同一个 `requestId` 会被幂等回放（返回上次结果，**不会重新执行**）。
2. **`code=4` 不是失败** —— 它表示「任务在后台跑，拿 `taskId` 轮询」。**千万别重发原请求**。
3. **批次失败可以原样重跑** —— 已建过计划的组合会被「查计划」查到 → 走 C1 复用 → **不会重复建计划**。

## 3. curl 自测（部署后按顺序验一遍）

```bash
# ① 探活（免 token）—— 确认服务活着、5 张表都可读
curl --noproxy '*' http://127.0.0.1:8080/actuator/health
curl --noproxy '*' -X POST http://127.0.0.1:8080/api/v1/task/ping \
  -H "X-Auth-Token: <你的 token>"

# ② 单条投放（先用一条真实数据试，dry-run 下不会真花钱）
curl --noproxy '*' -X POST http://127.0.0.1:8080/api/v1/task/planBuild \
  -H "X-Auth-Token: <你的 token>" -H "Content-Type: application/json" \
  --data-binary @planbuild.json
#   planbuild.json 内容：
#   {"requestId":"test-1","params":{"awemeShowId":"272886488","productName":"益生元身体乳"}}

# ③ 批量投放
curl --noproxy '*' -X POST http://127.0.0.1:8080/api/v1/task/processPending \
  -H "X-Auth-Token: <你的 token>" -H "Content-Type: application/json" \
  --data-binary @batch.json
#   batch.json 内容：
#   {"requestId":"test-batch-1","params":{"rows":[
#     {"row":4992,"awemeShowId":"272886488","productName":"益生元身体乳","videoId":7690503084850281061}
#   ]}}

# ④ 轮询（把 ③ 返回的 taskId 填进去；没有 code=4 就不用做这步）
curl --noproxy '*' http://127.0.0.1:8080/api/v1/task/t-xxxxxxxx \
  -H "X-Auth-Token: <你的 token>"
```

> ⚠️ **`--noproxy '*'` 必须加** —— 本机 curl 走代理会连不上 `127.0.0.1`。
>
> ⚠️ **中文参数写成文件用 `--data-binary @file.json`** —— 直接 `-d '...'` 在 Windows 终端有编码坑。

## 4. `code` 对照表：影刀该怎么处理

| `code` | 含义 | 影刀动作 |
|---|---|---|
| `0` | 成功 | 按 `data.cells` 写回表 |
| `1` | **业务失败** | **上报人工，不要重试**（`message` 可直接贴企微群） |
| `2` | **参数错误** | **改参数再调，不要重试** |
| `3` | **未授权** | 检查 token 配置，**不要重试** |
| `4` | **任务在后台跑** | 拿 `taskId` **轮询** `GET /api/v1/task/{taskId}`，**不要重发原请求** |
| `5` | 内部错误 | **可以重试**，但**必须带同一个 `requestId`**（幂等保护） |

## 5. `processPending` 应答怎么读

```json
{
  "code": 0,
  "data": {
    "submittedRows": 3, "combinations": 2,
    "succeeded": 1, "failed": 1, "skipped": 1,
    "cells": [ { "row": 4992, "column": "K", "value": "全域PC" },
               { "row": 4992, "column": "N", "value": "已投" } ],
    "results": [ ... ],
    "warnings": []
  }
}
```

| 字段 | 含义 |
|---|---|
| `submittedRows` | 提交了几行 |
| `combinations` | **去重后**的【抖音号+商品】组合数（同一组合多行只算一个） |
| `succeeded` / `failed` / `skipped` | 成功 / 失败 / 被跳过的**组合**数 |
| **`cells`** | **影刀按这个写表**（所有成功组合的写回指令已汇总） |
| `results` | 每个组合的明细（`status` = `OK` / `FAILED` / `SKIPPED`） |
| `warnings` | **必须看** —— 非空说明有些行没全部办成 |

**`cells` 里写什么**：

| 列 | 值 | 什么时候 |
|---|---|---|
| `K 投放类型` | `全域随心推` | 走了 A 场景（累计笔数不足 3，投随心推） |
| `K 投放类型` | `全域PC` | 走了 B / C1 / C2（乘方计划） |
| `N 投放状态` | `已投` | 上面两种情况都写 |

> ⚠️ **两列都写**（服务返回的 `cells` 里已经包含两条）。
> 只写 `K` 的话，`投放状态` 会一直停在「待投放」—— 而**只要有一次写 `K` 失败，下次扫表还会选中该行 → 重复投放（花钱）**。

## 6. 上线切换步骤（⚠️ 顺序不能反）

服务已经**新旧并存**：新任务和旧任务都能用，`processPending` 也不会影响现有调用。

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| **①** | 部署服务（配置保持 `dingtou.task.async-timeout-millis: 0`） | 默认**不转异步** → 行为与改造前一致，影刀侧无感 |
| **②** | 影刀流程改成「提交整批 + 拿 `cells` 写回」，**先用一两条真实数据试** | `dry-run` 默认开着，不会真花钱 |
| **③** | 验证没问题后关掉 dry-run（`dingtou.dry-run: false`） | 这时才真建计划 |
| **④** | 影刀加上「`code=4` 就轮询」的分支并验证 | 转异步要求影刀支持轮询 |
| **⑤** | 把 `async-timeout-millis` 设成 `30000`（30 秒） | 长任务不再让影刀干等 → 不会超时重试 → 不会重复花钱 |

> ⚠️ **④⑤ 顺序反了会断**：影刀还没支持轮询就打开转异步，
> 影刀会拿到一个 `taskId` 但不知道怎么用。

## 7. 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `code=3 未授权` | token 不对 | 检查 `X-Auth-Token` 是否等于服务端配的 `DINGTOU_AUTH_TOKEN`。⚠️ 若服务启动命令带了 `--dingtou.auth-token=xxx`，**环境变量不生效** |
| `code=2 参数错误: rows 必须是非空数组` | body 结构不对 | 用 `{"requestId":"...","params":{"rows":[...]}}` 的完整结构 |
| 同一个 `requestId` 第二次返回一模一样 | **正常** —— 幂等回放（防重复执行） | 换一个新的 `requestId` |
| `code=2 该 requestId 已用于 taskCode '...'` | 同一个 `requestId` 用在了两个不同任务上 | 换新的 `requestId`（**同一 requestId 不能跨任务复用**） |
| 素材表没变化，但 `cells` 有值 | **正常** —— 服务不写 Excel | 影刀要按 `cells` 自己写 |
| `failed > 0`，`warnings` 里有「没定位到账户」 | 素材表 `E 全域账号` 列是空的 / 不是账户字典里的名字 | 人工补表；⚠️ **服务只认精确匹配**，不做模糊纠错 |
| `warnings` 里有「没有授权达人」 | 该抖音号没授权给这个账户 | 先在千川后台完成达人授权 |
| `warnings` 里有「商品名匹配不到唯一商品 ID」 | 商品名重名 / 映射表没维护 | 人工补【商品 ID 映射表】 |
| `code=1 撞上频控` | 千川 40100 全局频控 | 服务已自动重试/退避；若仍失败，**错峰稍后重跑**（避开整点/半点） |

## 8. 一句话备忘

> **影刀只管搬运：读表 → 提交 → 写回。**
> 判断规则、账户定位、算 N、调千川 —— **全在服务里**。
> 看到 `code=4` 就轮询；看到 `code=1/2/3` 就上报人工**别重试**；批次失败**原样重跑**是安全的。
