# dingtou 全流程梳理

> 每个环节：**读什么表 / 调什么接口 → 得到什么信息 → 写到哪 / 代码在哪**。
> 更新：2026-10-08

---

## 〇、一句话

**影刀（RPA）只做「读写 Excel + 编排 + 企微交互」；所有业务判断与千川 API 调用都在本服务。**
影刀用 HTTP 调 `POST /api/v1/task/{taskCode}`，服务返回结果 + **要写回 Excel 的 cells**，影刀照着写。

### 表的列结构速查

**① 定投素材表**（A–N）

| 列 | 含义 | 备注 |
|---|---|---|
| A 日期 / F 视频发布日期 | `M.D` 文本 | ⚠️ 表里是**小数**，`9.19 < 9.2` → 按字符串拆 `.` |
| B 对接商务 | | |
| C 抖音名 / **D 抖音号** | **达人主键** | 字符串格式 |
| E 全域账号 | 账户名（**含脏值**，26 种取值只有 6 种能精确匹配） | ⚠️ 不做模糊纠错 |
| **G 产品** | **商品维度**（表里没有商品 ID） | |
| H 视频id | 抖音短视频 ID | ≠ 千川素材 ID |
| I 视频链接 | 分享口令/短链 | |
| J 定向情况 | | |
| **K 投放类型** | **空 = 尚未投放；非空 = 老数据（不管）** | ⚠️ **是输出字段**，不是筛选条件 |
| L 视频无效 / M 投放群 | | |
| **N 投放状态** | 原「投放备注」→ 改名 | 值：`待投放` / `已投` / **`投放中 M.D`** |

**⑥ 定向投放登记表**（**3 行复合表头**）

```
第1行(账户层)  A1:J1 官方店铺投放账户 | K1:N1 婴童店 | O1:P1 专卖店
              Q 对接商务 | R 达人抖音信息 | S 达人UID | T 合作码
第2行(分组层)  每 2 列一组 = 一个千川账户（A2:B2 官方【孕产-商品】/ C2:D2 官方【青少年-商品】/ …）
第3行(叶子)    A/C/E/G/I/K/M/O = 【投放商品】；B/D/F/H/J/L/N/P = 【授权状态】
第4行起        数据
```

⚠️ **P 列是「授权状态」（值=1），不是商品** —— 商品在**奇数列**。
⚠️ 第 1 行的账户号（如 `7742425`）是**店铺号**，不是千川账户 ID；账户名在第 2 行。
⚠️ 一格可能塞多个商品（`燕窝气垫，山茶花面膜`）→ 按逗号/顿号拆开比对。

**⑦ 高消耗达人7天未更新素材总表**（25 列）

| 列 | 含义 |
|---|---|
| A 投放千川账户 / B 投放类型 / **C 计划 ID** | |
| D 达人抖音名 / E 达人抖音号 / F 投放商品 / G 消耗金额 | |
| H 素材更新时间 / I 间隔天数 / **J 周期时间** | ⚠️ **J 列是子周期**（一个 sheet 合并好几周） |
| K 对接商务 / L 催更状态 / M 拒绝范围 / N 备注 / O 聊天记录截图 | |
| **P 交付状态** | ← **要写的列** |

## 二、5 大步骤全流程

### 步骤 1 · 前置校验（企微 @机器人）

| 项 | 内容 |
|---|---|
| **读什么** | 企微消息（区间 = 上次@后第一条链接 ～ 本次@前最后一条） |
| **调什么** | 千川【商品授权】/【达人授权】接口 |
| **得到什么** | ① 提抖音号 → 回填企微备注<br>② 解析商品 ID → 查【商品映射表】判断是否主推<br>③ 查该达人该商品的**定向 + 佣金** |
| **判定** | **佣金 = 5% 才写入素材表全字段** |
| **代码** | ⚠️ **未实现**（这段在影刀侧） |

### 步骤 2 · 商务二审

| 项 | 内容 |
|---|---|
| **读什么** | 素材表（人工填「可投放」/「不投放原因」，**新增两列**） |
| **调什么** | — |
| **得到什么** | 待投放行（`N 投放状态 = 待投放` 且 `K 投放类型` 为空） |
| **代码** | 影刀定时抓取并 @达人（⚠️ 服务侧只提供筛选口径） |

### 步骤 3 · 执行投放 ★ 核心

```
开始 → 待投放素材列表
  ↓
◇ 是否在《定向投放登记表》存在投放计划
  ├─是→ 获取千川计划列表 → 排除 DELETE / OFFLINE_AUDIT
  │       → ◇是否存在千川计划
  │            ├─是→ ◇计划是否为投放中 ├─是→ 添加素材 → 结束
  │            │                      └─否→ 记录异常表 → 结束
  │            └─否→ 创建乘方计划 → 结束
  └─否→ 获取随心推订单数 N
         ↓
       ◇ 是否随心推订单数 < 3
         ├─是→ ◇是否状态互斥（投放中/冻结/审核中/未开播/创建中）
         │      ├─是→ ◇随心推状态==投放中？
         │      │      ├─是→ 等待随心推投放结束先记录状态 → 结束
         │      │      └─否→ 记录异常表 → 结束
         │      └─否→ 创建心推订单 → 结束
         └─否→ ◇随心推状态==投放中？
                ├─是→ 等待随心推投放结束先记录状态 → 结束
                └─否→ 获取千川计划列表 →（汇入上面查计划那段）
```

#### 3.1 定位上下文（`PlanTargetResolver`）

| 项 | 内容 |
|---|---|
| **读什么** | 素材表（定位待处理行）+ 账户字典 + 商品映射表 + **定向投放登记表** |
| **调什么** | 【抖音号授权列表】接口（抖音号 → 数值 UID） |
| **得到什么** | `待处理行号` + `账户(名+ID)` + `商品ID` + `抖音数值UID` |
| **⚠️ 关键** | · 账户从**素材表 E 列**解析；**登记表命中则优先用登记表的账户**<br>· 待处理行**跨多账户** → 直接抛错（不自动挑）<br>· 账户**只认精确匹配**，不做模糊纠错 |

#### 3.2 算 N（`CumulativeCountService`）

| 项 | 内容 |
|---|---|
| **读什么** | **本地订单快照** `data/order-snapshot.jsonl` |
| **调什么** | 不调（快照由 `refreshOrders` 维护） |
| **得到什么** | `N = 该【抖音号 + 商品ID】的订单笔数` |
| **⚠️ 口径** | · **不看状态**？→ **看**：**白名单 7 个算**（`DELIVERY_OK`/`FROZEN`/`FINISHED`/`OVER`/`AUDIT`/`BOOK`/`CREATING`），**5 个不算**（`OFFLINE_AUDIT`/`FAILED`/`TIMEOUT`/`UNPAID`/`UNPAIDCANCEL`）<br>· 快照**不可用直接抛错**，不拿近似值定档 |

#### 3.3 查千川计划（`PlanQueryService`）

| 项 | 内容 |
|---|---|
| **调什么** | 【随心推全域计划列表】`/qianchuan/uni_promotion/list/`（`search_keyword_type=AWEME` 服务端按抖音号过滤） |
| **得到什么** | 该账户下该抖音号的计划（`ad_id` / `name` / `status` / `productIds`） |
| **⚠️ 口径** | · **排除** `DELETE`（已删除，⚠️ 接口实际值是 `DELETE` 不是 `DELETED`）/ `OFFLINE_AUDIT`（审核不通过）→ 当「没有计划」<br>· **计划状态为空时不判**（接口没给就别猜）<br>· 时间窗 ≤180 天；`uni_promotion/list` 约 **2 天延迟**，按 adId 复核走**详情**接口 |

#### 3.4 决策（`DecisionEngine`）

| 条件 | 场景 | 动作 |
|---|---|---|
| 已有计划 | **C1** | 复用计划：加本条素材 + 改名 |
| `N < 3` 且无计划 | **A** | 创建随心推订单 |
| `N == 3` 且无计划 | **B** | 创建乘方计划 + 加全部素材 |
| `N > 3` 且无计划 | **C2** | 创建乘方计划 + 加全部素材 |

#### 3.5 互斥检查（⚠️ **两个口径不同**）

| 动作 | 受哪些状态限制 |
|---|---|
| **创建随心推订单** | **5 个互斥状态**：`DELIVERY_OK` / `AUDIT` / `CREATING` / `BOOK` / `FROZEN` |
| **创建千川乘方计划** | **只判 `DELIVERY_OK`**（只为「等它跑完再建」）—— 同一抖音号 × 同一商品维度下，无论随心推什么状态基本都能建成功 |

**命中时**：在素材表 `N 投放状态` 写 **`投放中 M.D`**（带检测当天）→ 当天不再检测，**第二天自动顺延重测**。

#### 3.6 执行

| 场景 | 调什么接口 | 关键点 |
|---|---|---|
| **A 建随心推** | 【随心推全域订单创建】`/qianchuan/aweme/uni_promotion/order/create/` | 必填 `advertiser_id`/`aweme_id`(数值UID)/`delivery_setting`/`marketing_goal`/`product_id`；约束见 `SuixintuiConstraints`（启动自检 + 组装前校验） |
| **B/C2 建乘方计划** | 【乘方计划创建】`QianchuanOverallVideoCreateV10Api` | ⚠️「乘方」= `deliverySetting.qcpxMode = QCPX_MODE_ON`（**不是** `QianchuanAdCreateV10Api`） |
| **C1 加素材** | 【计划可投素材池】+【添加素材】`/qianchuan/uni_promotion/ad/material/add/` | **增量**添加（原有素材不动）；⚠️ 别用 `overall_video/update`（**全量**，会抹掉原素材） |
| **C1 改名** | 【计划名修改】`/qianchuan/uni_promotion/ad/name/update/` | ⚠️ 请求体**只有** `ad_id`+`advertiser_id`+`name`；别用 `ad/update`（可能覆盖预算/ROI） |

#### 3.7 写回素材表（返回 cells 给影刀）

| 列 | 值 |
|---|---|
| `K 投放类型` | `全域随心推` / `全域PC`（乘方场景） |
| `N 投放状态` | `已投` / **`投放中 M.D`**（跳过等） |

### 附 · 达人巡查 / 催更（`kolPlanCostQuery`）

| 项 | 内容 |
|---|---|
| **读什么** | 达人巡查配置表（账户+阈值）+ 千川计划消耗 |
| **调什么** | 【随心推全域计划列表】+【计划详情】 |
| **得到什么** | 消耗达标的计划清单（投放中 + 有消耗 + 消耗 ≥ 阈值） |
| **可选** | `withAweme=true` 附带抖音号/抖音名；`checkDelivery=true` 做**交付状态检查** |

**交付状态检查**（`DeliveryStatusChecker`）：

| 项 | 内容 |
|---|---|
| **读什么** | 《高消耗达人7天未更新素材总表》 |
| **找哪批行** | 找【上一个周日】→ 取**结束日 == 该周日**的 sheet → 再筛 **`J 周期时间 == 该周日`** 的行 |
| **调什么** | 【乘方计划详情】（拿计划名） |
| **判定** | 计划名里的 `M.D` 落在 **[上周期结束日, 本周期开始日]** → 「已交付」；否则「未交付」；**解析不出 → 留空** |
| **写到哪** | `P 交付状态` 列（**服务直接写**，写前自动备份） |

## 三、接口清单（千川侧）

| 用途 | 接口 | 备注 |
|---|---|---|
| 抖音号 → 数值 UID | `/qianchuan/uni_aweme/authorized/get/` | 只能按**抖音号**搜 |
| **数值 UID → 抖音号** | `/qianchuan/aweme_auth_list/get/` | ⚠️ `aweme_id` 必须传**数组**；一次请求，~1 秒 |
| 查计划 | `/qianchuan/uni_promotion/list/` | `adlab_scene` **两个场景都要查**（`UNI_PROJECT` + `OVERALL_PROJECT`）；约 2 天延迟 |
| 计划详情 | `/qianchuan/uni_promotion/ad/detail/` | 实时；`aweme_infos[].unique_id` 有时为空 → 用 `aweme_uid` 反查 |
| 计划可投素材池 | `/qianchuan/uni_promotion/block_material/get/` | ⚠️ 分页是 **`cursor` + `has_more`** |
| 添加素材 | `/qianchuan/uni_promotion/ad/material/add/` | **增量** |
| 计划改名 | `/qianchuan/uni_promotion/ad/name/update/` | 请求体只有 3 个字段 |
| 建乘方计划 | `QianchuanOverallVideoCreateV10Api` | `qcpxMode = QCPX_MODE_ON` |
| 建随心推 | `/qianchuan/aweme/uni_promotion/order/create/` | 参数约束见 `SuixintuiConstraints` |
| **拉随心推订单** | `/qianchuan/aweme/uni_promotion/order/get/` | **没有达人/商品过滤** → 只能拉全量本地分组；不传时间窗 = 拉全量 |
| 订单详情 | `/qianchuan/aweme/uni_promotion/order/detail/` | |

**Token**：两个客户端 `SuixintuiTokenClient`（`shop_suixintui`）/ `QianchuanTokenClient`（`shop_qianchuan`），
URL 都是 `https://aocilenda.cn/qianchuan/callback?action=token&state=...`。
⚠️ 频控三层 `40130/40110/40100` + 5 分钟惩罚。

## 五、写回 Excel 的方式

| 表 | 谁写 | 方式 |
|---|---|---|
| **定投素材表** | **影刀 或 服务** | 默认**服务直写**（`dingtou.source.direct-write=true`，带备份）；⚠️ 开了之后影刀**不要再写**，否则互相覆盖 |
| **交付状态表（P 列）** | **服务直接写** | 全量重写目标列 + **写前备份**（`.backup-yyyyMMdd-HHmmss.xlsx`） |
| **异常表** | **服务直接写** | **追加一行** + **按天备份**；文件不存在自动创建 |

## 七、必记的坑（精选）

1. ⚠️ **素材表日期是小数** → `9.19 < 9.2`，按字符串拆 `.`
2. ⚠️ **商品名不能用映射表做名称映射**（60 个商品名只有 38 个精确匹配；映射表用「（次链）」后缀区分同名 SKU，素材表从不带）
3. ⚠️ **`adlab_scene` 必须两个场景都查**，否则查不到自己建的计划
4. ⚠️ **幂等必须做**（`requestId` 落盘）—— 影刀重试不可控，重复建计划**要花钱**
5. ⚠️ **别让影刀死等**：超时返回 `code=4 + taskId` 让影刀轮询
6. ⚠️ **SDK 业务错误不抛异常**（`code != 0` + `data == null`）→ 必须主动 `checkResponse()`
7. ⚠️ **SDK 枚举常量名 ≠ 接口值**（如 `video_schedule_type` 常量名 `FROM_NOW`，接口值 `SCHEDULE_FROM_NOW`）
8. ⚠️ **共享盘路径必须带 IP**（机器名解析不了）
9. ⚠️ **Excel 独占锁**：被 Excel 打开时「能读、能新建，但无法写入/重命名目标文件」
10. ⚠️ **素材标题互斥规则**：素材**全是**「抖音主页视频」→ 不能带 title；有非主页视频/图片 → 必须至少一条 title
